# Freight Elevators 0.1.13 validation

Tested 1 November 2026 on Windows Steam Satisfactory CL 513885 with SML 3.12.0.

Incoming and outgoing item-stack reservations are independent per floor. Both arrays save and replicate. The Reservations panel selects the buffer explicitly. Outgoing admission counts stored items and assigned cargo, permits shared overflow, and protects the unused allocation of other items. Unloading rechecks the current rules and retains blocked cargo onboard. Changing a rule never deletes or relocates items automatically. Existing saves retain incoming rules and start with no outgoing rules.

Four editor suites and 107 Windows dedicated-server integration checks passed. The 13 added checks cover default capacity, independent buffers/floors, shared overflow, invalid and over-capacity rules, pre-existing excess cargo, destination routing, in-flight accounting, unloading, partial stacks, changes after pickup, and rule removal. Prior incoming-belt, native power, fluid, and transport checks remain green. No remote multiplayer client, Epic runtime, or Linux runtime test was performed for this update.

The user's live factory was saved through the native UI as <private-save> and backed up before installation. SHA-256: F8CAE8158F88B132A9D482331CD5DBBF4BC6280E18057C79D43A137CB54395C5. The opt-in local repair targets the explicitly named 48m and 16m stops on the same tower. It reserves five outgoing Iron Rod stacks, returns only the plates necessary to free the allocation to existing incoming storage, verifies the plate total before/after, then waits for normal rod routing and delivery. No fixtures are spawned in the user's factory. Autosave is disabled during validation.
